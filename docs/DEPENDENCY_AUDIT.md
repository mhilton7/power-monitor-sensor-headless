# Dependency audit

Pinned production inputs:

| Dependency | Pin | Use |
|---|---|---|
| ESP-IDF | tag `v6.0.2`, commit `7101770dc6db2667b3c477cc31365dd1acd6db4e`, CI OCI index `sha256:0d8c9773d48a327233f9c1d7c654ff0bcf133ae24503ea2e97a57cfe02b8cb67` | framework, bootloader, FreeRTOS, drivers, TLS/PSA, OTA, NVS, FATFS |
| Espressif cJSON | `1.7.19~2`, service component | bounded JSON protocol parsing/serialization |
| Python | `3.11.15` in CI; exact requirements plus supported-wheel SHA-256 hashes | host simulator/release evidence |

There is no Arduino core, AsyncTCP, ESPAsyncWebServer, MQTT client, sensor HTTP server, or cloud telemetry SDK. Project C compiles warnings-as-errors. `dependencies.lock` is generated by the ESP-IDF component manager and committed. The release records its SHA-256 and framework commit, and emits an SPDX 2.3 package plus dependency graph for every component in ESP-IDF's `project_description.json` rather than a hand-written summary.

GitHub workflows pin third-party actions by full commit and the ESP-IDF container by tag plus immutable OCI index digest. `tools/audit_dependencies.py` makes live TLS-verified OSV queries for the exact ESP-IDF commit, Espressif cJSON wrapper commit, and upstream cJSON v1.7.19 package identity. Any returned active vulnerability, network error, incomplete response, stale/mismatched report, or nonzero scanner exit blocks packaging. The passing raw machine report is copied unchanged into the checksummed release pack.
