# Hardware identity gate

Checked 2026-08-15. The operator supplied AliExpress item `2255800916232238` (underlying product object `4001102546990`), marketed as a PZEM-004T classic TTL Modbus meter with a 100 A external CT. Peacefair's current product page identifies the external-CT unit as PZEM-004T-100A 4.0, and the linked six-page specification identifies model PZEM-004T-100A-D-P. The specification confirms 80–260 V, 0–100 A, 0–23 kW, 45–65 Hz, power factor, cumulative Wh, TTL UART at 9600 8N1, default slave 1, and the exact function 0x04/start 0/count 10 register layout implemented here. Seller V3/V4 naming is not treated as physical identity evidence.

Consequently the implemented `pzem-004t-v4-classic-candidate` remains a protocol-profile candidate, not a verified production identity. RC8 sets `CONFIG_PM_PZEM_LIVE_VALIDATION=y` and performs the exact strict, read-only transaction so the marked unit can produce real validation evidence; it keeps `CONFIG_PM_HARDWARE_IDENTITY_VERIFIED=n`. Stable builds continue requiring verified identity. Disabled/default builds return `not_verified`, while the RC validation profile returns real `ok`, timeout, framing, CRC, address, function, or range status. No simulated reading can enter the physical path.

A stable build still requires exact ESP32-S3/module markings, PZEM model/revision/terminal markings, CT marking/type/rating, SD module marking, photo hashes, measured UART voltage behavior, captured 9600 8N1 frames/register scaling, energy-counter behavior, and a passing 72-hour marked-unit suite. The evidence must validate against `release/hardware-certification.schema.json`, match the firmware commit and image SHA-256, and pass `test/hardware/verify_evidence.py`. A seller URL, protocol-compatible frame, or simulation never satisfies this gate.
