# Storage recovery

Mount never auto-formats. Startup checks write/flush/rename/reopen, loads the persistent card UUID, validates headers/records, truncates an interrupted trailing partial record, and rebuilds retained sequence bounds by scanning segments. A damaged header is renamed into quarantine; a bad record is reported with an unavailable range and valid surrounding records remain independently decodable. A new writable segment is used after damage.

When a card is absent, read-only, full, or unmountable, the sensor remains useful: PZEM sampling, live heartbeat, commands, and diagnostics continue. It never redirects historical readings into flash. Full-card handling reclaims only oldest wholly acknowledged segments; unsynchronized records are never deleted merely to continue logging. If no safe segment is reclaimable, writes stop with exact oldest/newest/ack status and automatically resume after safe space/card service.

Capacity and free space are read from the mounted FAT volume with ESP-IDF's supported `esp_vfs_fat_info` API. A failed or incoherent capacity query is a storage I/O failure, never evidence that the card is full. Authenticated heartbeats report both byte counts together (or both as unavailable), and the dashboard displays the latest persisted pair.

Whole-card format is explicit prepare/commit. The server supplies a 16-byte lowercase-hex confirmation token; the device accepts it for no more than 600 monotonic seconds in the same boot. Prepare reports acknowledged and unacknowledged record counts. After exact commit authentication, an A/B CRC journal atomically records the intent while removing the token. Commit runs through the sole storage task and can repeat the format idempotently after power loss. It preserves config, enrollment/device identity, sequence floor/ack/reset generation, and OTA state, then assigns a new card UUID/generation. The exact original command result remains durable until a signed heartbeat response acknowledges it; recovery evidence is never cleaned up merely because the filesystem operation returned success.
