# Outbound commands

Commands arrive only in authenticated heartbeat responses for their owning device. The redundant CRC-protected NVS ledger keeps eight recent IDs/idempotency keys and resumes interrupted work. It enforces `not_before`, expiry, duplicate identity, valid state transitions, and nondecreasing 0-100 progress. The 136 KiB encrypted production NVS partition leaves garbage-collection headroom beyond a compile-time conservative A/B durable-blob budget; the firmware does not rely on a custom recovery partition.

Implemented types: `reboot`, `maintenance_sleep`, `sync_now`, `diagnostics_snapshot`, `network_self_test`, `meter_self_test`, `storage_self_test`, `format_storage_prepare`, `format_storage_commit`, `apply_configuration`, `rotate_device_credentials`, `ota_install`, `data_reset_prepare`, `data_reset_commit`, and `data_reset_cancel`. States match protocol: queued, delivered, accepted, running, succeeded, failed, expired, cancelled, superseded, awaiting reboot/heartbeat, and rolled back.

Destructive format/reset commands use a server-generated 16-byte lowercase-hex confirmation token. A prepare is valid for at most 600 monotonic seconds in its originating boot session. An A/B, read-back-verified CRC NVS journal persists the prepare type, command IDs, expiry, token, reset generation, sequence boundaries, loss counts, and a random boot-session marker. Reboot invalidates and erases a merely prepared record because its monotonic deadline cannot be compared safely across boots; the server must issue a fresh prepare.

Once an exact commit payload and token have been authenticated, firmware atomically persists `COMMIT_INTENT_PERSISTED_TOKEN_ZEROIZED`: the durable intent contains no token or boot marker. Recovery then idempotently advances through the applicable sequence-floor, storage-format, and reset-configuration phases. It finally persists the original command's exact structured result in the redundant command ledger. The destructive journal is retained until a signed heartbeat response authenticates that the server accepted that exact result; only then is `RESULT_ACKNOWLEDGED` persisted and cleanup attempted. Power loss after any durable boundary resumes the same command and byte-identical evidence. A new prepare, cancel, or unrelated command cannot erase an in-flight commit. Failed, expired, cancelled, and successfully consumed token paths zeroize token-bearing RAM, and a mismatched reset-cancel ID cannot erase another prepare.

Payload and evidence shapes are locked by `test/vectors/device-destructive-commands.json`. In particular, reset prepare returns exactly `prepare_command_id`, `reset_generation`, `server_sequence_floor`, actual `sequence_floor`, and `ready`. The server signs the commit with that authenticated actual floor. Reset commit success returns exactly `prepare_command_id`, `reset_generation`, and the actual committed `sequence_floor`. Reset cancel accepts exactly `{prepare_command_id}` and success returns exactly `{prepare_command_id,cancelled:true}`. No result evidence includes a confirmation token or secret. Explicit structured evidence is sent unchanged; generic `attempt` or diagnostic decoration is not added to it.

Credential rotation uses the separately versioned `pm-credential-rotation/1.0.0` payload contract in `test/vectors/device-credential-rotation.json`. Prepare carries an exact 32-byte lowercase-hex server-generated candidate secret, its full lowercase SHA-256 fingerprint, a UUID rotation ID, and an absolute overlap expiry. Firmware verifies the fingerprint before an A/B, CRC/read-back-verified rotation journal records the candidate and an inactive config slot is staged without activation. The secret-bearing command payload is replaced durably by its SHA-256 immediately after journal persistence, so duplicates remain comparable without retaining the secret in the command ledger. Temporary serialized payload, parsed response-tree, command-stack, and response-buffer copies are explicitly zeroized; the secret is never logged or returned. Production firmware requires NVS encryption; the candidate is zeroized from RAM and the rotation journal when an old-key-authenticated commit intent becomes durable.

Commit carries only schema, rotation ID, and fingerprint. It is accepted under the old active server-to-device key, atomically records `COMMIT_INTENT_SECRET_ZEROIZED`, activates the staged slot idempotently, derives the new directional keys, and retains the exact `{rotation_id,credential_fingerprint,activated:true}` result until the server acknowledges it in a response authenticated under the new keys. A result-awaiting-ack ledger entry is pinned and cannot be evicted by later commands. The prepare result is exactly `{rotation_id,credential_fingerprint,ready:true}` under the old key. Reboot resumes every stage. Without trusted UTC, a prepared candidate remains dormant and commit fails closed; once trusted time proves expiry, it is erased. Exact cancel `{schema,rotation_id,cancelled:true}` clears only the matching pre-commit candidate and returns `{rotation_id,cancelled:true}` under the old key. Post-commit cancel is rejected; after authenticated result acknowledgement the inactive old config and journal are erased.

Reboot flushes storage/checkpoints first and reports the original command after boot. Remote maintenance sleep is limited to 10-3600 seconds; there is no indefinite remote shutdown and no claim that sleep removes mains power. Completion is not success until the server receives authenticated result evidence.
