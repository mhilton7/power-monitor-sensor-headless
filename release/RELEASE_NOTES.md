# PowerMeter Sensor Headless 0.1.0-rc.5

This release candidate carries forward the ESP32-S3 headless measurement agent, authenticated outbound protocol, append-only microSD outage journal, USB/COM provisioning and repair, durable commands, and dual-slot OTA rollback. RC5 updates only release identity and immutable cross-repository traceability for the audited server RC5 contract. Firmware runtime behavior, device protocol, schemas, configuration, and hardware-certification status remain unchanged from public RC4.

Its exact enrollment, heartbeat, reading-batch, permanent-loss, OTA-download, destructive-command, credential-rotation, HKDF, and base64 HMAC contracts are locked by cross-repository vectors and validated against the compatible PowerMeter V2 server `v0.1.0-rc.5`. The complete generated server OpenAPI document is bound by SHA-256 `66b4e1cfb0f5a5797dadd9a8783ff0b192ca416d1f4264c135a4e380b2b94591`. Firmware also authenticates server response bytes, timestamps, and nonces before applying acknowledgements or commands.

Public firmware RC4 remains immutable. Its matching server RC4 passed compatibility, mandatory test/security/migration gates, four image publications and attestations/scans, and anonymous GHCR access, but the digest-pinned deployment smoke restarted the completed one-shot initializer during runtime-only recovery. The unchanged initializer `FinishedAt` assertion failed, assembly was skipped, and no server RC4 GitHub Release, YAML, manifest, or checksum bundle exists. RC5 changes only that server smoke orchestration/diagnostics and release identity; it makes no server runtime, API, protocol, or migration change beyond the RC5 OpenAPI `info.version` identity reflected by the binding above.

Credential rotation stages the server-generated candidate in an inactive CRC/read-back-verified config slot, commits under the old directional key, reports activation under the new key, and retains a byte-stable result until authenticated acknowledgement. The A/B rotation and destructive-operation journals resume after power loss at each durable boundary; secret-bearing temporary buffers and consumed tokens are explicitly zeroized.

The PZEM-004T V4-classic register layout remains a candidate driver. Stable production promotion is blocked until the exact marked unit, TTL electrical behavior, register map, OTA rollback, and 72-hour soak pass the machine-readable hardware certification gate. The release-candidate build therefore refuses to present simulated samples as production evidence.

All energy, interval, completeness, and uploaded history evidence originates only from validated PZEM frames. Utility-bill content is outside this firmware and cannot enter its measurement or storage path.
